# 按当前未知选择方法

方法服务于本轮决定，不是固定流水线。不要求同事逐题填完56步。读当前所选方法的使用约定，然后只问与目标有关且尚未回答的问题；在brief中记明采用、复用或跳过的依据。

| 当前情况 | 先用 | 何时接续 |
| --- | --- | --- |
| 只有想法、功能名或“效率低” | [M01](sop/M01.md) 问题与反证简报 | 真实行为信息不足，M02；核心情境已知，M05 |
| 好评、主观确信，缺最近事件 | [M02](sop/M02.md) 行为访谈 | 先向同事问已知事件；真实访谈未发生保持未验证。需要借Demo取证时接M03 |
| 不确定哪种方式更好，需要原型比较 | [M03](sop/M03.md) 最小实验 | 明确原型要观察什么，再M05；对齐会仅评价体验就不能证明付费 |
| 决定投入正式开发还是继续验证 | [M04](sop/M04.md) 构建决策 | Demo只是输入之一；需求方选择不自动等于上线授权 |
| 场景清楚，需明确本轮Demo范围 | [M05](sop/M05.md) 范围与验收 | 定义范围、状态、验收；生成后M08 |
| 多人接手或跨会话继续 | [M06](sop/M06.md) 上下文任务包 | 维护brief、review、文件入口和下一问题 |
| 本地无法打开或依赖运行条件 | [M07](sop/M07.md) 可复现环境 | 优先离线单文件；必须用服务时说明依赖并复验 |
| 准备交付Demo | [M08](sop/M08.md) 分层验证与授权 | 功能通过、语义覆盖、业务未知分别报告 |
| 要证明省时或价值 | [M09](sop/M09.md) 价值与交付度量 | 先定义基线和口径，Demo不捏造收益 |
| 已有价值支持，验证获客渠道 | [M10](sop/M10.md) 渠道与增长实验 | 可做渠道实验模拟，不执行真实投放 |
| 已有流程延误/返工 | [M11](sop/M11.md) 失败与瓶颈复盘 | 先看全链路；需要时原型演示改善方案 |
| 问题在职责/协作/成长，而非软件缺失 | [M12](sop/M12.md) 团队任务与成长 | 用HTML演示流程、责任与异常升级，不强行新增系统 |
| 试用后修订方法 | [M13](sop/M13.md) 方法版本演进 | 收集有来源的建议，不自行升级团队基线 |
| 多项目资源冲突，需排下一决定 | [M14](sop/M14.md) 项目决策队列 | 有证据再比较；不发明精确优先分数 |

常见轻量路线：M01澄清 → 必要时M02/M03取证设计 → M05界定Demo → M08检查 → M06交接。M04用于实际投入决定，不是每次画原型都必须通过的关卡。

## 在原型对齐任务中的适配

下列适配仅限本Skill制作离线对齐原型，不能用于跳过正式开发、上线或真实业务操作的条件：

- M05提到的M04决定，在本轮Demo中可由用户已授权的原型任务与范围摘要代替；这只说明允许做原型，不证明价值已验证或允许正式投入。
- M01中泛化问题不能直接开发，指不能把未澄清假设当作正式构建依据。用户希望先看探索原型时可实现假设场景，但要显式说明这些假设及原型要帮助回答的问题。
- M08的放行范围绑定具体动作。功能缺陷影响核心路径就修复；环境不能运行浏览器时可交付“未浏览器验证的草稿”，不能称为已验证可演示版。真实业务证据未知不阻断用于获取该证据的原型，但阻断“效果已验证”等结论。
- M01/M06/M12涉及真人复核、独立接手或团队试用时，未发生就标未执行并列为后续，不拿Agent自检冒充真人反馈。它们不自动成为所有离线Demo的交付门槛；若用户明确要求某项验收，则仍须完成或报告未达成。

例如“AI销售助手，跟进很乱”：先区分漏承诺、找不到信息、优先级不清，再选择核心任务。若答案是“最近三次临时换人漏掉客户承诺”，Demo就围绕交接核对；不能自动扩成CRM、预测销售额和自动群发。
