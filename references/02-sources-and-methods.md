# 来源、比较与方法索引

## 1. 来源边界

F：创始人手册本地译本（维护者原件，未随包提供）。定位采用本地文件行号及章节；它是第三方分享的中文翻译，原始出版身份、翻译准确性、时效性未在本轮外部核验。

A：AI Native 研发范式实践手册（维护者原件，未随包提供）。定位统一为 **PDF 物理页码**，不是印刷页码；正文物理第 6 页对应印刷第 1 页。用户称为阿里最新发布的手册；本文只确认本地材料自述与内容，不独立确认“最新”及官方发行渠道。

完整覆盖及输入指纹见阅读记录（维护者原件，未随包提供）。下面是释义与归纳，不是原文引语。“材料提出”与“实际成立”不同；案例数字属于作者报告，不能推断因果或公司收益。本轮不采用具体提效数字、模型排名、SDK 示例或标准版本作为实施承诺。

## 3. 综合比较

| 类型 | 对照 | 本版处理 |
|---|---|---|
| 共同点 | F-E02/E03 与 A-E01/E02：快速产出要接受真实反馈 | 用证据与决策连接工作，不把产物数量当成果 |
| 互补 | F-E01–E05 提供创业阶段；A-E05–E10提供执行基础 | 生命周期为纵向主线，执行能力跨阶段调用 |
| 互补 | F-E04/E05减少创始人瓶颈；A-E06/E11说明知识、权限、组织条件 | 从可复用任务和明确职责试起，保留培养路径 |
| 张力 | F-E03的明确需求/范围与 A-E03对固定流程的批评 | 固定目标、红线和验证条件；可调整实现路线，改变目标需负责人重新判断 |
| 张力 | F-E02强调先验证问题，A-E02案例早期进入真实原型 | 对陌生问题先查真实行为；对已有业务的交互不确定性可尽早原型。原型只证明所测假设 |
| 来源内张力 | F 第4章强调MVP安全，第5章谈到测试期可能尚无敏感数据 | 按真实数据和操作风险判断，不能因“MVP”标签放松安全 |
| 张力 | A-E11讨论角色融合，同时承认知识传承、焦虑与成长问题 | 只提出职责与学习设计，不提前决定组织形态 |
| 空白 | 两份材料均未给出完整多项目资源分配体系 | P视角与M14明确是用户需求驱动建议，待试用 |
| 空白 | 财务经营、销售定价、团队激励及特定行业要求覆盖不足 | 保留任务缺口，不把“全公司AI native”写成已经完备 |

## 4. 候选方法索引

每行给出调用入口；14 项方法均已细化为[四步 SOP 与问题清单](sop/README.md)。M01–M04 另有贯通流程与演示（维护者原件，未随包提供）。进入实际任务时仍需补充业务标准。全部状态：**内部待试用，v0.1**。负责人是建议职责，尚未任命具体人员。

| ID / 方法 | 触发与输入 | 行动 → 产物 | 检查与失败处理 | 建议负责人 / 来源 |
|---|---|---|---|---|
| M01 问题与反证简报 | 模糊想法；目标、人群与已有线索 | 分解假设、比较替代方案 → 问题简报 | 不能说明行为与损失则返回澄清 | 项目负责人；F-E02 |
| M02 行为访谈 | 问题假设；可触达对象 | 询问最近事件与处理过程，记录反例 → 证据表 | 好评不算行为；人群不符则分组重采 | 研究执行者；F-E02 |
| M03 最小验证实验 | 关键未知；证据表、约束 | 预设通过/失败条件，比较人工或轻量原型 → 实验记录 | 仅测体验不能声称付费验证；缺观察则未知 | 项目负责人；F-E02/E03、A-E02 |
| M04 构建决策 | 访谈、实验、成本与风险 | 对照标准并审视反证 → 继续/转向/暂停/停止记录 | 不确定则购买下一条证据而非全面开发 | 业务决策者；F-E02/E03；四类结论为综合设计 |
| M05 范围与验收约定 | 准备MVP或变更；目标与证据 | 列范围、非目标、不可变约束及可变假设 → 任务规格 | 验收无法观察则重写；范围变更更新依据 | 产品/项目负责人；F-E03、A-E03 |
| M06 上下文任务包 | 人/Agent交接；规格、知识、当前状态 | 整理最少足够上下文、版本与未知 → 可交接任务包 | 新执行者无法定位或启动则补缺；不塞全部资料 | 技术负责人；A-E02/E05/E06 |
| M07 可复现环境 | 开发/验证失败；仓库、配置、依赖 | 保存运行定义与隔离数据，干净实例复验 → 定义及运行证据 | 依赖现场手调则未完成；反馈缺失先修环境 | 工程负责人；A-E07 |
| M08 分层验证与授权 | 准备交付/实际操作；变更、目标、权限 | 机器检查+语义复核+按需真实实验 → 检查报告与决策 | 任一必需项未知就不放行该动作；目标变化重检 | 业务及资源负责人；F-E03、A-E08/E09 |
| M09 价值与交付度量 | 准备试用；目标、基线、成本 | 同时跟踪采用、质量、交付和客户结果 → 指标与观察记录 | 指标冲突查分母、范围、复杂度；不归因于AI单因素 | 项目负责人；F-E03、A-E04/E10 |
| M10 渠道与增长实验 | 价值初获支持；客群、渠道、单位成本 | 单一可解释假设的小规模获客试验 → 转化/留存/经济性记录 | 获客增长但留存或经济性恶化，暂停扩张 | 增长负责人；F-E04/E05 |
| M11 失败与瓶颈复盘 | 延误、质量下降或运营故障；过程证据 | 定位全链路约束，补回归案例 → 改进任务及结果 | 局部提效无整体改善则换瓶颈假设 | 交付负责人；A-E01/E10、F-E04 |
| M12 团队任务与成长设计 | 协作反复依赖个人；职责与技能缺口 | 显式判断/执行/复核，安排结对及独立练习 → 责任与学习计划 | 无原作者无法使用，或成长机会消失则修订 | 团队负责人；A-E11、F-E05；练习机制为建议 |
| M13 方法版本演进 | 新研究或项目复盘；来源与结果 | 候选→试用→限定采用→修订/撤回 → 版本记录 | 无真实结果不得内部已验证；反例影响原适用范围则降级 | 方法维护者；A-E06/E10及本项目综合设计 |
| M14 项目决策队列 | 多项目并行；项目卡与资源约束 | 对比下一决策、阻塞、证据成本 → 优先级与负责人 | 数据不可比则保留未知，禁止虚构评分 | 用户/项目统筹者；用户需求，F-E01/A-E04仅为间接启发 |

方法被采用时另建实践记录：项目ID、方法ID及版本、场景、基线、预设标准、实际输入/操作/结果、成本、副作用、反证、决定、负责人、日期。该记录才是后续公司方法迭代的证据。
